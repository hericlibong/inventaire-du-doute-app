# Roadmap de lancement

## Phase 0 - Socle indépendant

- [x] Créer un dépôt et un historique Git distincts.
- [x] Écrire la relation avec le dépôt source.
- [x] Ajouter une synchronisation reproductible des exports.
- [x] Versionner un premier snapshot sans reproductions binaires.
- [x] Vérifier le chargement par un écran technique minimal.

## Phase 1 - Cadrage produit

- [ ] Définir les utilisateurs prioritaires.
- [ ] Écrire trois à cinq scénarios d'usage concrets.
- [ ] Arrêter le MVP et ses non-objectifs.
- [ ] Choisir le nom public et la relation visible avec le site éditorial.
- [ ] Définir les états qui doivent être partageables par URL.

## Phase 2 - Contrat de données 1.0

- [ ] Projeter les exports historiques dans des structures propres à la webapp.
- [ ] Définir un schéma pour le manifeste, les artistes, les œuvres et les musées.
- [ ] Ajouter des tests de contrat et de compatibilité.
- [ ] Séparer explicitement données descriptives et fichiers d'images.
- [ ] Documenter la procédure de mise à jour d'un snapshot publié.

## Phase 3 - Prototype du parcours principal

- [ ] Prototyper recherche → artiste → profil → filtres → œuvre → musée.
- [ ] Utiliser un échantillon représentatif avant le corpus complet.
- [ ] Concevoir ordinateur et mobile comme deux usages du même outil.
- [ ] Vérifier clavier, toucher, états vides et URL partageable.
- [ ] Valider le parcours avant de généraliser le design.

## Phase 4 - Comparaison et montée en charge

- [ ] Comparer deux ou trois profils sur une même échelle.
- [ ] Charger les détails par artiste à la demande.
- [ ] Mesurer recherche, filtres, carte et longues listes sur le corpus complet.
- [ ] Décider sur mesures si un backend devient nécessaire.
